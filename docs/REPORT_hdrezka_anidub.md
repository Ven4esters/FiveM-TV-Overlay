## anidub — работает

### Как устроен

```
anidub.com/<id>-<название>.html
   └── <iframe src="https://player26.ladonyvesna2005.info/index.php?v=/s9/<hash>&playlist">
         └── HTML плеера: <video data-stream-src="vid.php?v=%2Fs9%2F<hash>">
               └── vid.php → master: fhd.mp4 (1280x720) + sd.mp4 (854x480)
                     └── chunk.m3u8 → сотни .ts со звуком внутри
```

Три вещи, которые стоит помнить:

1. **Хост плеера цифровой.** В ТЗ записан `player.cdnvideohub.com`, в реальности
   это `player26.ladonyvesna2005.info`. Номер, судя по всему, меняется вместе
   с балансировкой, поэтому адрес берётся из iframe страницы, а не
   подставляется константой. Из этого же следует: путь `vid.php?v=…` надо
   склеивать с адресом плеера, а не с доменом anidub.

2. **Плеер у серий кладётся по-разному.** У одной серии это `<iframe>`,
   у другой — только вкладка `<span data="…">` без iframe. Читаем оба, иначе
   половина серий «без плеера».

3. **Подпись одноразовая, CDN меняется.** Каждый запрос `vid.php` отдаёт новый
   хост (`cdn1…cdn5`), новый `vodN` и новый `md5`; протухшая ссылка отвечает
   403 «Angie». Значит: резолв делается заново при открытии, а сегменты тянет
   наш мост — он ходит свежими запросами сам.

### Что проверено

```
Резолв:   «Операция: Семейка Ёдзакура 3 сезон 7 серия»
          720p → кадр 1280x720, 3139 кбит/с (настоящий BANDWIDTH)
          480p → кадр  854x480, 1639 кбит/с
Сессия:   tNkqCUHH
Плеер:    readyState 4, кадр 854x480, 371 декодированный кадр,
          183 КБ звука, ошибка видео = нет, ошибок консоли 0
```

Скриншот: `docs/screenshots/v2/anidub_play.png` — кадр из самой серии.

### Заголовки

CDN anivids отвечает **403 на ffmpeg-отпечаток** (`Lavf/…`) и 200 на
Chrome-UA. Для браузера это неважно — мост подставляет заголовки сам.
Но замер громкости идёт мимо моста, поэтому UA и Referer кладутся
в `Stream.headers` вместе с потоком.

## hdrezka — упирается в регион, и это не поломка

### Как устроен

```
hdrezka.ag (или зеркало hdrezka-home.tv)
   └── Anubis: JS-задача «Проверяем, что вы не бот!» — решается за ~8 секунд
         └── страница: sof.tv.initCDNSeriesEvents(<id>, <translator_id>, …)
               └── POST /ajax/get_cdn_series/
                     id, translator_id, action=get_movie, is_tv, cdn_quality
                       └── JSON: url (master с подписью) + quality (список высот)
```

Поток в HTML не лежит вообще: его отдаёт только AJAX, и уходит он с cookies
и Referer браузерной сессии. Поэтому источник имеет два входа: `resolve()`
честно говорит «нужна браузерная сессия», а работу делает `resolve_html()`,
которому передают готовый HTML страницы и функцию запроса.

### Что именно мешает с нашего IP

Сервер разработки стоит в США. С этого адреса сайт отвечает так:

```json
{"success": true, "premium_content": 1, "url": false, "quality": false}
```

и пишет в плеере: «К сожалению, это видео не доступно в вашем регионе».
**Одинаково и для премиум-фильма, и для обычного сериала** — то есть это
не «платно», а именно гео.

Чтобы убедиться, что дело в IP, а не в языке: подменял `locale=ru-RU`
и часовой пояс на московский — ответ не изменился. Решает адрес, а не
настройки браузера.

### Что с этим сделано

- `premium_content` и `url: false` **не считаются поломкой источника**;
  текст плеера читается отдельно и переводится в `GeoblockedError`:
  «Видео недоступно из вашего региона → выберите другое видео».
- Пока не отработала JS-задача Anubis, страница-заглушка распознаётся
  отдельно: «страница ещё не открылась, подождите секунду».
- Состояние источника — 🟡 `partial`, а не 🟢: без браузера и вне России
  он не открывается, и писать «работает» было бы неправдой.

### Как проверить у себя

На вашем компьютере (Россия) тот же запрос отдаёт нормальный `url`.
Проверка — `check_link.bat`: перетащите на него ссылку с hdrezka, скрипт
покажет поток и качества с **вашего** IP.

```
check_link.bat https://hdrezka.ag/films/drama/<id>-<название>.html
```

Если у вас тоже «недоступно в регионе» — значит видео правда закрыто
правообладателем, а не сломалось у нас.

## Дополнение 24.11.2026: у anidub появился второй сайт

Заказчик прислал ссылку `anidub.org/6093-van-pis-tv.html`, и выяснилось,
что это **другой сайт с другим плеером**. Прежний разбор (`anidub.com`)
работает — но только на `.com`.

| | anidub.com | anidub.org |
|---|---|---|
| Плеер | `player*.ladonyvesna2005.info` (iframe) | `<video-player>` + API cdnvideohub |
| Поток | HLS, `cdn*.anivids.link` | прямые mp4, `vd*.okcdn.ru` (VK) |
| Качества | 720p, 480p | **до 1080p** (6 вариантов) |
| Озвучки | нет выбора | **4–5 на серию, 9 студий** |
| Браузер | не нужен | не нужен |

Оба домена обслуживаются, каждый своим модулем: `anidub.py` и `anidub_org.py`.
Ссылки разводятся по домену — проверено тестами в обе стороны.

### Как вскрыт новый плеер

```
GET https://anidub.org/6093-van-pis-tv.html
    → <video-player data-publisher-id="19" data-aggregator="cvh"
                    data-title-id="019169b6-9f49-7086-a8d3-76f1e2558ffa">

GET https://plapi.cdnvideohub.com/api/v1/player/sv/playlist?pub=19&aggr=cvh&id=…
    → 615 КБ JSON: 3759 дорожек, 1180 серий, 9 озвучек

GET https://plapi.cdnvideohub.com/api/v1/player/sv/video/<vkId>
    → mpeg…Url (прямые mp4) + hlsUrl + duration

GET mpegFullHdUrl (первые 256 КБ)
    → tkhd: 1920x1080
```

Ключ не нужен, cookies не нужны, браузер не нужен.

### Четыре ловушки, каждая стоила отдельного разбора

**1. Подпись привязана к браузеру, а не только к IP.** API выдаёт её под
тот UA, которым пришёл запрос, и пишет это в ссылку: `srcAg=GECKO`. CDN
отвечает 400 тому, кто не совпал. Наш `fetch()` для okcdn.ru по умолчанию
ставил Chrome — и получал 400 на правильный адрес. Проверено: одна и та же
ссылка → 206 на Firefox-UA, 400 на Chrome-UA. Теперь один UA на **все**
запросы, включая мост (через `Stream.headers`).

**2. `moov` у okcdn весит 1,5 МБ.** Размер кадра лежит в `tkhd` в начале,
но обход атомов требовал, чтобы контейнер поместился в буфер целиком — и
размер читался как 0. Теперь в контейнер заходим, даже если он не влез.

**3. hls.js не разбирает mp4 — и молчит.** Если отдать мастер, где варианты
это mp4-файлы, hls.js не сыграет НИЧЕГО и не напишет ни одной ошибки.
Добавлено поле `Stream.is_direct_file`: плеер при нём не использует hls.js,
а меняет `video.src`, возвращаясь на ту же секунду.

**4. `__LEVELS__` подставлялся только в скрипт.** Список качеств живёт в
разметке, а замены шли по SCRIPT: плеер читал заглушку как JSON и падал.
Ошибка была в консоли, но видео просто стояло на нуле.

### Паузы до старта

| | до правок | после |
|---|---|---|
| резолв | 32,4 с | **8,8 с** |
| смена озвучки | 35,7 с | **4,6 с** |

Что дало: пробы размеров идут параллельно (было последовательно), плейлист
кэшируется на 10 минут по title-id (615 КБ на каждое переключение озвучки —
это дорого), размеры файлов кэшируются по id файла (подпись в адресе
меняется, id — нет).

### Проверено живьём

Chromium через наш мост: **1920x1080**, 201 кадр декодирован, 1500 с,
панель v2 работает (пауза, перемотка), ошибок в консоли нет.

Осталось честно: серия выбирается первая (сайт продолжает с 1180-й, но
для человека, открывающего сериал, первая честнее). Выбор серии появится
вместе с историей просмотров.
