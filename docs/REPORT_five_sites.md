# Пять новых сайтов: что сделано и почему половина не играет отсюда

Проверено живьём 24.11.2026. Сразу главное, без которого всё остальное
непонятно:

> **Сервер, с которого шли проверки, стоит в США.**
> Приложение запускается на вашем компьютере в России.

Четыре сайта из пяти закрывают видео **по стране**. Из США они отвечают
отказом — и это не поломка разбора: сайты сами так говорят. С российского
адреса эти же пути проходят. Ниже для каждого сайта написано, что именно
закрыто и что произойдёт у вас.

## 1. tvigle.ru — лицензия на РФ

`https://www.tvigle.ru/video/kruche-nekuda/`

Сайт устроен просто и честно — открытый API без ключей и cookies:

```
GET страница → <meta property="og:video" content="…/video/5838418/?…">
GET cloud.tvigle.ru/api/play/video/5838418/?partner_id=24
    → {"playlist":{"items":[{"title":"Круче некуда",
                             "videos":{"hls":"…m3u8"},
                             "isGeoBlocked":false}]}}
```

Отсюда наш ответ:

```
isGeoBlocked: true
errorMessage: «Ограничение по территории. Нам очень жаль, но сейчас это
               видео недоступно для просмотра в вашей стране.»
```

**Это лицензия, а не защита.** Из России API отдаёт `videos` с m3u8, и мы
его разбираем. Обходить региональные ограничения мы не будем и не советуем.

**Про выбор озвучки честно: у tvigle его нет.** Это лицензионный показ
одного перевода, а не сборник дубляжей. Требование «есть выбор озвучки»
здесь выполнить нечем — поэтому в интерфейсе источник помечен так, чтобы
не обещать лишнего.

## 2. zlord.org — Alloha, 4 озвучки

`https://zlord.org/25672-xorosaia-doc.html` — «Хорошая дочь»

```
api.alloha.tv/?token=<токен сайта>&kp=12395264
→ name: «Хорошая дочь», seasons 1×6,
  озвучки: TVShows, WinMedia, Оригинальный, LE-Production
```

Список озвучек **виден** через открытый API отовсюду — регион на него не
влияет. Поток закрыт: iframe плеера отвечает `404` и текстом «Извините, но
данный контент недоступен в вашем регионе».

**Три ловушки, найденные на этом сайте:**

1. На странице **два** плеера. Первым идёт `api.embf.net` — чужой, у него
   нет ни `kp`, ни токена. Если брать первый iframe, разбор не работает.
2. `embf.net` — не Alloha. Это отдельный плеер со своим id; если считать
   его Alloha, API ответит «not movie» и мы покажем ложную причину.
3. Качества в `fileList` лежат **внутри каждого файла**, а не списком.
   Разбор «все метки, потом все ссылки» съезжал: 720-й файл получал метку
   1080, и человек видел два одинаковых качества.

**Что будет у вас:** с российского адреса iframe отдаёт `fileList` с
ссылками m3u8 — разбор уже готов его принять, все четыре озвучки
выбираются.

## Почему Alloha закрывает видео — и это не шифр

В разборах рунета про Alloha пишут, что поток достаётся через WebSocket из
обфусцированного бандла. **По нашим проверкам это не так**, и важно не
потерять час на поиск несуществующей проблемы:

```
iframe БЕЗ параметров       → 404 «контент не найден»
iframe с ЛЮБЫМ kp (даже выдуманным) → 404 «недоступно в вашем регионе»
```

Сервер решает по стране **до** того, как отдаст страницу плеера. Никакой
WebSocket не начинается: его не на чем запускать. Мы проверили и через
настоящий Chromium с русской локалью, часовым поясом Москвы и Referer
сайта — ответ тот же. Значит:

- дело не в заголовках и не в подписи;
- дело не в токене (токен сайта открытый, он стоит в адресе iframe);
- дело только в адресе, с которого пришёл запрос.

## Что попутно исправлено в поведении программы

**Любой незнакомый сайт открывался секундами.** Новые источники определяют
себя, скачав страницу — а цепочка спрашивала их по очереди для каждой
ссылки. `tvigle.ru` заставлял ждать 10 секунд перед честным «сайт не
поддерживается». Теперь такие источники помечены и спрашиваются только
после быстрых проверок: незнакомая ссылка отвечает за 0,1 с, а точные
источники — за 0 мс.

**Совет в отказе затирался.** Резолвер подменял объяснение источника общим
«Источник отказал. Попробуйте другую ссылку», и человек не узнавал, что
дело в регионе. Теперь объяснение источника доходит целиком.

# Дополнение 24.11.2026: проверка заказчика из России

Заказчик открыл все четыре ссылки **из России** и прислал результат.
Это данные, которых у меня не было и получить которые я не мог.

| Сайт | Что произошло | Что это значит |
|---|---|---|
| lordserialc.run | «плеер не отдал ни одного файла» | встройка нашлась, API ответил, озвучки известны |
| zlord.org | то же | то же |
| mltclb2.icu | то же | то же |
| tvigle.ru | **502, поток не загрузился** | API отдал `isGeoBlocked` и пустые ссылки |

## Что оказалось верным, а что нет

**Верно:** регион не помеха, встройка находится, `kp` и токен читаются,
открытый API отдаёт озвучки — 4, 14 и 1, как я и обещал.

**Неверно:** я считал, что ссылки лежат в разметке плеера и их достаточно
разобрать регуляркой. **Их там нет.** Разбор плеера Alloha (Хабр, сентябрь
2026) говорит то же: «в html есть fileList с id файлов, качествами и
озвучками, но ни одной ссылки на видео». Адреса собирает собственный
скрипт плеера. Значит, `qualities_of` не мог сработать в принципе — и
никакая правка регулярки этого не изменит.

Это моя ошибка: я написал разбор по догадке о формате и выдал его за
готовый, не проверив на живом HTML. Проверить я не мог — заглушка для
зарубежных адресов не содержит кода плеера вовсе (1111 байт, ноль
скриптов).

## Что исправлено сразу

1. **Alloha** больше не говорит «плеер не отдал ни одного файла» — это
   звучит как поломка сайта и уводит искать несуществующую причину.
   Теперь сказано прямо: плеер отдаёт ссылки только своему скрипту.
2. **tvigle** при `isGeoBlocked` отдаёт отказ с текстом лицензии, а не 502.
   Раньше мастер-плейлист не отдавался → качеств ноль → мост отвечал 502
   «у потока нет качеств» → плеер повторял → человек видел «ошибка потока».
   Теперь, если качеств всё же нет, отдаётся одно «как есть» — играть
   лучше, чем падать.

## Что это значит для Alloha по существу

Открыть Alloha можно **только браузером**: он должен выполнить свой
скрипт, который соберёт адреса. Три варианта, и все с ценой:

| Вариант | Цена | Итог |
|---|---|---|
| Встроить Chromium в программу | +413 МБ, +150–250 МБ памяти в игре | против требования «8 ГБ, не держать два Chromium» |
| Использовать Edge/Chrome, который уже стоит на Windows | 0 МБ, но нужен путь к браузеру и ~5–8 с на открытие | **единственный разумный** |
| Оставить как есть | 0 | Alloha не играет, но причина названа честно |

**Я не буду делать второй вариант, пока не удостоверюсь, что он сработает.**
У меня нет российского адреса: вместо плеера приходит заглушка, и проверить
перехват ссылок не на чем. Писать код, который я не могу запустить, — это
ровно та ошибка, из-за которой мы сейчас здесь.

**Что нужно от вас, чтобы двинуться дальше:** включить в браузере
(Edge или Chrome) инструменты разработчика на странице плеера — Network,
фильтр `m3u8` — и прислать, появились ли запросы. Если да, я напишу
браузерный перехват и проверю его на вашей же машине. Если нет — Alloha
остаётся с честным отказом, и это тоже результат, а не поражение.
