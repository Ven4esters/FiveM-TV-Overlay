# ADR-0001: Слоистая структура пакета

**Дата:** 2026-11-23
**Статус:** принято

## Контекст

Проект вырос из набора скриптов в папке: 14 модулей, 9000 строк, все
в одном каталоге. `overlay.py` (2108 строк) содержал UI, логику запуска
прокси, историю и обработку сети. `proxy.py` (1867 строк) содержал
HTTP-сервер, 30 маршрутов в одном методе и разбор сайтов.

Проблемы:
- невозможно понять, где бизнес-логика, а где транспорт;
- `do_GET` — 458 строк, сложность 90 при лимите 15;
- тестировать нечего: всё связано через глобальные переменные и сокеты.

## Решение

Разложить по слоям в `src/tvhost/`:

| Слой | Содержимое | Может импортировать |
|---|---|---|
| `core/` | бизнес-логика: закрепление, загрузка | стандартная библиотека |
| `infra/` | сеть, ffmpeg, кеш, диагностика, сайты | `core` |
| `web/` | страница-плеер (HTML/JS/CSS) | `core` |
| `ui/` | панель PySide6 | `core`, `infra`, `web` |
| `proxy.py` | HTTP-транспорт и маршруты | все слои |

Направление зависимостей проверяется тестом `tests/test_architecture.py`.

## Последствия

**Хорошо:**
- `core` и `infra` тестируются без сокетов и Qt (112 тестов без сети);
- маршрут = метод, `do_GET` стал 23 строки;
- новый источник добавляется одним методом `_prepare_*`.

**Плохо:**
- импорты стали длиннее (`from ..infra import sources`);
- при переносе модулей легко сломать импорт — ловится в CI сразу;
- все точки входа запускаются как модули: `python -m tvhost.proxy`,
  `python -m tvhost.core.download` (и `.bat`-ярлыки, и `ProxyController`);
  проверяется тестом `tests/test_entrypoints.py`.

## Альтернативы

- **Оставить плоско, только разбить do_GET** — дешевле, но проблема
  тестируемости остаётся: `proxy.py` всё ещё тянет Qt-независимый код вперемешку.
- **Полный DDD с репозиториями** — избыточно для локального приложения
  на одного пользователя (нарушает YAGNI).
