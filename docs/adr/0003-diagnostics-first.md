# ADR-0003: Диагностика — часть продукта, а не отладка

**Дата:** 2026-11-23
**Статус:** принято

## Контекст

Пользователь сообщил: «в тестах всё открывается, у меня нет».
Разбор шёл наугад, потому что приложение не вело журнал: маршрут `/hls`
был в списке «не писать в лог», а ошибки страницы-плеера вообще
не покидали телевизор. Каждая итерация занимала часы догадок.

## Решение

Диагностика — обязательная функция:

1. **Каждый значимый запрос логируется** (`/hls`, `/new`, ошибки CDN).
   `QUIET_PREFIXES` больше не включает `/hls`.
2. **Страница-плеер сообщает о себе** через `bootReport()`: User-Agent
   телевизора, наличие hls.js и MSE, размер экрана. Если через 12 секунд
   видео не готово — отправляется причина.
3. **Журнал переживает перезапуск**: пишется в `diag.log` с ротацией 2 МБ,
   при старте восстанавливается в память.
4. **Отчёт собирается одной кнопкой** и копируется в буфер.
5. **Секреты вырезаются** до записи в отчёт.

## Последствия

**Хорошо:**
- причина ошибки находится по отчёту, без доступа к машине;
- три состояния различаются по первой строке: `boot` есть/нет, `hls=`;
- регресс: `tests/test_diagnostics.py` (19 тестов).

**Плохо:**
- журнал занимает до 2 МБ на диске;
- запись на каждый сегмент — небольшой оверхед (≈0.1 мс, измерено).

## Альтернативы

- **Только файл, без окна** — пользователь не найдёт и не пришлёт.
- **Только в памяти** — теряется при падении, то есть в самый нужный момент.
