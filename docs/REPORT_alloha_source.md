# Alloha: как плеер получает адреса видео (полная расшифровка)

**Дата:** 24.11.2026. **Кому:** заказчику и тому, кто будет это поддерживать.
**Итог одной строкой:** цепочка разобрана целиком, до последнего шага; последний
шаг (`POST /bnsi/movies/<id>`) с зарубежного адреса отвечает «контент не
найден» на любой id — это региональная проверка, а не наша ошибка.

## 2. Что такое расшифровка и почему без неё было никак

Скрипт плеера (`build/app.c63ca8da.js`, 734 КБ) обфусцирован
obfuscator.io: все строки вынесены в массив из 2208 элементов, а обращения к
ним идут по вычисляемым индексам (`Yl(0xa62,0xcf7)` — это, например, `POST`).
Плюс самозащита: массив прокручивается на 394 позиции при загрузке, так что
«взять строку по номеру» с листа не работает.

Ключ к снятию — то, что все функции-обёртки сводятся к одной:

```
function Yl(Q,y){return a0y(Q- 910, y);}          ← объявлена в каждой функции своя
function qY(Q,y){return a0qk(Q, y- -0x56);}
function a0qk(Q,y){return a0y(y- -0x22b, Q);}
function a0y(Q,y){Q=Q-(0x3ef*9+0xc7*-0x2f+0x283); var d=a0Q(); return d[Q];}
                                        ↑ 353 — смещение в массиве
```

То есть `F(a,b)` — это просто `pool[(a - const)]`. Дальше два шага:

1. пул берём не из литерала, а **исполняем** загрузку в node (`a0Q()` + IIFE
   самозащиты) — получаем массив уже после прокрутки;
2. разрешаем имена алиасов **по позиции вызова** — одно и то же имя `Yk`
   объявлено в файле десятки раз с разными смещениями, и «последнее
   определение» даёт мусор. Правильное — ближайшее ПРЕДЫДУЩЕЕ.

Контроль качества расшифровки: `window[qY(0x1da,0x509)]` → `consoleLog`,
`self['webpackChunk']` собирается из своего вызова. Если бы смещение было
неверным, совпадений бы не было.

## 3. Цепочка целиком

### 3.1 Что лежит в разметке плеера

Заказчик прислал `/home/user/uploads/alloha_player.html` (15 029 B). В нём:

```js
const userParam = { token: '5286c49a…', domain: '…', autoplay: 0, … };
const movie     = { id: 'dc27f0f0f45c4989af12f74b6a7757', type: 'movie' };
const fileList  = { type: 'serial', active: {id: 1836882, id_file: '1836464', …}, all: {…} };
```

- адресов видео **нет** — только номера (`id`, `id_file`);
- `<meta name="viewporti" content="WF1ENlE6…">` — 88 символов, «семечко» для
  одной из частей заголовка `Borth`;
- `window.__ws_factory` — обёртка над `WebSocket`, чтобы отличить настоящий
  браузер от подделки.

### 3.2 Отпечаток браузера → `Accepts-Controls`

Функция `c0()` (в расшифровке — на позиции ~499 000) собирает массив строк и
возвращает `sha256(join('||'))` от:

1. `navigator.userAgent`, очищенный от версий (`(\d+(?:[._]\d+)+)` → `''`);
2. `Intl.DateTimeFormat().resolvedOptions().timeZone`;
3. `screen.width x height` (большая сторона первой);
4. `navigator.language`;
5. `navigator.deviceMemory`, `navigator.hardwareConcurrency`;
6. canvas: `toDataURL()` после `fillText('fp', 10, 10)`;
7. WebGL: `UNMASKED_VENDOR_WEBGL|UNMASKED_RENDERER_WEBGL`;
8. `OfflineAudioContext` (длительность отрендеренного осциллятора).

Этот же хеш уходит HLS-библиотеке в заголовке `Accepts-Controls` и в
`xhrSetup`/`fetchSetup` для каждого запроса манифеста и фрагмента.

**Важно:** для CDN (`userplay.live`) он не нужен — проверено перебором, там
достаточно `Origin` домена плеера (см. §6). `Accepts-Controls` относится к
серверу плеера, а не к CDN.

### 3.3 `Borth`: отпечаток + перестановка `meta viewporti`

```js
headers: { 'Borth': iF + '|' + iP(iR(iS(iZ, iz), iz)) }
```

- `iZ` = `content` меты `viewporti` (88 символов);
- `iS` — разбиение на группы по числу бит индекса (старшая группа первой);
- `iR` — то же разбиение, но группы собираются в обратном порядке;
- `iP` — псевдослучайная перестановка: позиции обходятся шагом `26` по
  модулю простого числа ≥ длины, берутся только `< длины`;
- `iF` — отпечаток (та же `c0()` либо предыдущий ответ сервера).

Проверено: `iP(iR(iS(meta))` воспроизводится полностью — см.
`/tmp/borth3.js`, результат в §7.

### 3.4 Запрос, который отдаёт адреса

```js
hF = fileList.type === 'trailer' ? '/trailers/' : '/movies/';
hQ.ajax('/bnsi' + hF + hq, {
    method: 'POST',
    data: { token, av1: config.av1Support, autoplay, [_ref], audio, subtitle },
    headers: { Borth: iF + '|' + iP(...) },
    // jQuery по умолчанию: application/x-www-form-urlencoded; charset=UTF-8
}).done(function(hX, hk, hp) {
    //  hX.pnr, hX.pnk   → адрес WebSocket (?sid=pnk)
    //  hX.hlsSource[]    → массив озвучек
});
```

Ответ `hlsSource` — это то, что нам нужно:

```js
player._wsHlsSource = hX.hlsSource;
// у каждого элемента: { label, default, quality: { "<высота>": "<адрес>" }, audioId }
```

Дальше плеер берёт `quality[hf]` (высота из настроек), режет по строке
`' or '` (резервные адреса в одной строке) и отдаёт `hls.loadSource(...)`.
Тот самый 1964-символьный путь из HAR — элемент `quality["428"]`.

### 3.5 WebSocket — зачем он

`hX.pnr` — адрес вида `wss://…`, к нему добавляется `?sid=<pnk>&v=2.1&t=<time>`.
Сервер присылает сообщения `config_update` с полем `edge_hash`:

```js
if (hz.type === 'config_update' && hz.edge_hash) {
    cq = hz.edge_hash;      // токен для acceptis/Accepts-Controls
    cE = hz.ttl * 1000;
}
```

То есть WebSocket **не отдаёт URL** — он отдаёт токен edge и TTL.
Адрес уже лежит в ответе `POST /bnsi/...`. Это опровергает прежнюю
гипотезу «адрес приходит по WebSocket», которая держала нас три итерации.

## 4. Проверка POST: почему он не работает снаружи России

Маршрут верный — это доказывает формат ответа:

| Запрос | Ответ | Значит |
|---|---|---|
| `POST /bnsi/serial/1836882` | 404 HTML | маршрута нет |
| `POST /bnsi/movies/` | 404 HTML | маршрута нет без id |
| `POST /bnsi/movies/1836882` (реальный id) | 404 JSON «контент не найден» | маршрут есть, файл не найден |
| `POST /bnsi/trailers/1836882` | 404 JSON | маршрут есть |
| `POST /bnsi/movies/1` (выдуманный) | 404 JSON | **тот же ответ** |

Дальше — проверка, что дело не в запросе:

| Что меняли | Результат |
|---|---|
| `Content-Type`: form-urlencoded / JSON | 404 JSON, тот же текст |
| `Borth`: реальный суффикс / `0\|…` / `x\|y` / пусто | без разницы |
| `token`: свой сайта / `token_movie` / мусор 32 символа | без разницы (пустой → HTML, т.е. запрос без токена не доходит до проверки) |
| `Authorizations: Bearer <guard>` (238 символов) | без разницы |
| `Origin`/`Referer`: плеер / zlord / без них | без разницы |
| `X-Forwarded-For`, `X-Real-IP`, `CF-Connecting-IP`, `True-Client-IP` на российский адрес | без разницы |
| `Accept-Language: ru-RU` | без разницы |

Вывод: проверка региона стоит **до** поиска файла и читает настоящий IP
соединения. Ни один id, токен или заголовок не проходит. С российского
адреса этот же запрос отдаёт `hlsSource` (у заказчика плеер играет).

## 5. Что это значит для продукта

1. **Озвучки** — работают отовсюду: их отдаёт открытый `api.alloha.tv`
   (проверено: `translation=93|96|338|241` → «Оригинальный», «TVShows»,
   «WinMedia», «LE-Production»). Это и есть то, что заказчик просил отдельно.
2. **Поток** — с российского компьютера путь проходит целиком: приложение
   само сделает `POST /bnsi/movies/<id>`, получит `hlsSource`, а мост
   проиграет CDN (проверено живьём, §6). С зарубежного адреса — честное
   «плеер отдаёт адреса видео только российскому адресу».
3. **Ошибку переписали**: прежний текст «плеер отдаёт ссылки только своему
   скрипту» теперь не соответствует правде — скрипт мы расшифровали. Новый
   текст называет точную причину и точное место.

## 6. CDN Alloha: что нужно мосту (проверено живьём)

`userplay.live` проверяет **только `Origin` домена плеера**:

| Заголовки | Ответ |
|---|---|
| только `User-Agent` | 403 |
| только `Origin: https://tories-as.stravers.live` (без UA) | 200 |
| `Origin` + испорченный на 1 символ путь | 403 |
| `Origin` + `Referer` + cookies + `Accepts-Controls` | 200 |

Сквозная проверка через мост (коммит `f622975`):
`/stream/<sid>` → 200 (мастер), `/hls?url=…` → 200 (подплейлист),
первый сегмент → 200, 1 736 609 байт.

**Вывод:** как только адрес получен (на машине в России), воспроизведение
работает. Блокер не в мосте, а в получении адреса.

## 8. Что делать дальше (и чего НЕ делать)

**Делать:**

1. Запустить приложение на компьютере в России и проверить живой Alloha —
   путь известен, код готов, нужен один `POST`.
2. Если на российской машине `POST /bnsi/movies/<id_file>` вернёт 200 —
   сохранить тело ответа: это единственный недостающий образец, по нему
   сразу пишется парсер `hlsSource` (структура уже известна).

**Не делать:**

- не перебирать заголовки для `POST /bnsi` — проверено, дело не в них;
- не искать «шифр» в WebSocket — он отдаёт токен, а не адрес;
- не пытаться обойти регион заголовками (`X-Forwarded-For` и т.п.) —
  сервер читает настоящий IP;
- не гонять headless-браузер с зарубежного адреса — страница плеера просто
  не отдаётся (404 до скриптов).

## 9. Технический итог по прошлым отчётам

| Прежнее утверждение | Статус |
|---|---|
| «адрес приходит по WebSocket» | **неверно**: по WS приходит токен `edge_hash` + TTL |
| «Borth — это guard-токен» | **неверно**: guard (238 симв.) нужен только для `Authorizations`; `Borth` = отпечаток \| перестановка меты |
| «CDN хочет Accepts-Controls» | **неверно**: CDN хочет `Origin` плеера |
| «адрес серверный, клиент его не считает» | **верно**: он в ответе `POST /bnsi/movies/<id>` |
| «нужен браузер заказчика» | **неверно**: нужен российский IP, браузер не обязателен |
