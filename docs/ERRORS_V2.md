## ERR-069 — Rutube: видео «есть», но поток не отдаётся (правообладатель)

**Дата:** 23.11.2026
**Ссылка-воспроизведение:** `https://rutube.ru/video/e1c3757f9a3db09a224ac95c836cecbf/`

**Симптом.** yt-dlp падает с `HTTP Error 404`, хотя страница открывается.

**Разбор.**
| Запрос | Ответ |
|---|---|
| `GET /video/<hash>/` (страница) | 200, HTML |
| `GET /api/video/<hash>/` (метаданные) | 200 — «Супермен \| Superman (2025)» |
| `GET /api/play/options/<hash>/` | **отказ**: `blocking_rule` |

**Причина.** Правообладатель ограничил показ за пределами РФ. Из
песочницы (IP США/за рубежом) поток недоступен. Видео при этом живое:
из России откроется.

**Решение.** Отдельный тип ошибки `RightsBlockedError`:
- НЕ помечает источник «сломан» (`state=OK`);
- в интерфейсе говорит «правообладатель ограничил показ», а не «ошибка»;
- не тратит повторный запрос на embed — запрет он не обойдёт.

**Урок.** «404» ≠ «видео нет». Для Rutube это чаще «скрыто от этого IP».
Проверять `blocking_rule` в ответе API до того, как отдавать пользователю
слово «ошибка».

## ERR-070 — `sorted(list_extractors())` падает с TypeError

**Симптом.** `AttributeError: 'TenPlayIE' object has no attribute '__name__'`.

**Причина.** `yt_dlp.extractor.list_extractors()` возвращает **экземпляры**
классов, а не строки. Часть экземпляров обращается к атрибутам, которых
у класса нет.

**Решение.** `type(obj).__name__` для каждого элемента, `sorted(key=str)`.

## ERR-071 — Kodik: прямая ссылка на плеер показывает «страницы не существует»

**Дата:** 23.11.2026
**Ссылка:** `https://kodikplayer.com/seria/1420137/746cbbd95c6ac9b2bd8c113953f63646/720p`

**Симптом.** Открытое напрямую окно показывает «Извините, но данной
страницы не существует». В iframe — работает.

**Причина.** В JS плеера:
```js
if (!isIframe() && location.hostname !== "localhost") { …подмена… }
```

**Решение.** Открывать через локальный iframe-обёртку (или через
`location.hostname = localhost`-подмену). Это же снимает вопрос
Referer-проверки.

**Найденный поток:** `https://p12.solodcdn.com/s/m/<base64>/<подпись>:<срок>/360.mp4:hls:manifest.m3u8`.
Подпись живёт ~сутки → кэш 12 часов.

## ERR-069 (дополнение) — как отличить блокировку от поломки

**Проверено на двух ссылках заказчика (23.11.2026):**

| Видео | Что сказал Rutube | Разрешено в |
|---|---|---|
| Супермен (2025) | `blocking_rule` | только РФ и СНГ |
| Гарри Поттер (2001) | `blocking_rule` + текст «…или у вас включён VPN» | **32 страны из ~250** |

**Точный способ проверки — до попытки воспроизведения:**

```http
GET https://rutube.ru/api/video/<hash>/
→ 200, в теле:
   "restrictions": {"country": {
       "allowed":    ["RU", "BY", "KZ", ...],   # где смотреть можно
       "restricted": ["US", "DE", "GB", ...]    # где нельзя
   }}
```

**Что это даёт.** Вместо «не удалось получить видео» можно сказать
человеку точно: «это видео доступно в 32 странах, ваша не входит».
Или наоборот — «у вас должно работать, дело в чём-то другом».

**Правило.** Для Rutube `blocking_rule` и `404` на
`/api/play/options/` — это **не** поломка источника.
Источник остаётся 🟢; недоступно конкретное видео с конкретного IP.

**Инструмент для заказчика:** `check_link.bat` —
запускается на его компьютере и проверяет ссылку с его IP,
то есть из страны, где видео может быть разрешено.
