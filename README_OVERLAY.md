# 🎮 GTA Video Overlay — полная инструкция

Оверлей-пульт поверх GTA 5: вставляете обычную ссылку на видео → получаете прямую ссылку для телевизора в игре. Всё локально, ничего не уходит в интернет кроме самих видео.

---

## 1. Быстрый старт (3 шага)

### Шаг 1. Запуск (он же установка)

Дважды кликните **`start.bat`** — единственный файл запуска.

**При первом запуске** он автоматически:
1. Проверит, установлен ли Python (нужна версия 3.12+).
2. Создаст папку `.venv` — изолированное окружение, чтобы не засорять систему.
3. Обновит pip и установит зависимости: `yt-dlp`, `PySide6`, `imageio-ffmpeg` (ffmpeg внутри pip — отдельно ставить не нужно).
4. Проверит, что всё встало.
5. Запустит оверлей.

⏱ Первый запуск займёт 1–3 минуты (+ интернет для зависимостей). **Все следующие запуски** — просто мгновенный старт оверлея, без установки.

**Если Python не найден** — скрипт скажет об этом. Скачайте Python 3.12 с [python.org](https://www.python.org/downloads/) и **обязательно поставьте галочку «Add python.exe to PATH»** при установке, затем запустите `start.bat` снова.

После установки появится тёмная панель — оверлей. Он:
- всегда поверх других окон (в том числе игры),
- живёт в трее задач как отдельное окно,
- автоматически поднимает видео-прокси на порту 9000.

### Шаг 2. Использование в игре

1. **Запустите GTA 5** и играйте в оконном режиме без рамки (Borderless) — так оверлей удобнее всего.
2. Откройте оверлей: он уже поверх игры, справа сверху.
3. Вставьте ссылку в поле ввода → нажмите **«Получить прямую ссылку»**.
4. Нажмите **«📋 Копировать»**.
5. В игре подойдите к телевизору / откройте мод → вставьте ссылку.

## 2. Управление видео из оверлея (пульт)

### Как это работает

Обычная прямая ссылка (`/get?url=...`) даёт телевизору **голый файл** — управлять им из игры нельзя. Поэтому есть второй режим: оверлей создаёт **страницу-плеер** `/player/<id>`. Телевизор открывает её, а оверлей становится пультом.

```
Оверлей                          Прокси                        Телевизор в игре
   │                                │                                 │
   │ «📺 Открыть на ТВ»             │                                 │
   ├─── /new?url=... ──────────────►│                                 │
   │◄── /player/abc123 ─────────────┤                                 │
   │        (копируется в буфер)    │                                 │
   │                                │◄──── открывает /player/abc123 ──┤
   │                                │──── HTML + <video> ────────────►│
   │  ⏸ ⏪ ⏩ 🔊 CC ⛶  громкость     │                                 │
   ├─── /control/abc123?cmd=pause ─►│                                 │
   │                                │◄──── /cmd/abc123 (опрос 250мс) ─┤
   │                                │──── исполняет: pause ──────────►│
   │                                │◄──── /report (состояние) ───────┤
   │◄── /state/abc123 ──────────────┤                                 │
   │   (позиция, длительность,      │                                 │
   │    громкость, играет/пауза)    │                                 │
```

### Что можно делать из оверлея

| Кнопка | Команда | Что делает |
|---|---|---|
| **▶ / ⏸** | `toggle` | Пуск и пауза |
| **⏪ / ⏩** | `seekRel` | −10 / +10 секунд |
| **Полоса прогресса** | `seek` | Перемотка в любое место |
| **🔊** | `mute` | Звук вкл/выкл |
| **Ползунок громкости** | `volume` | Громкость 0–100 % |
| **CC** | `subs` | Субтитры вкл/выкл |
| **⛶** | `fullscreen` | Развернуть/свернуть экран |
| **⏹** | `restart` | Остановить и начать с начала |
| **Качество** (выпадающий список) | `quality` | Выбрать 1080p / 720p / 360p или «Авто» |
| **Озвучка** (выпадающий список) | `trans` | Выбрать озвучку (Kodik и подобные кинотеатры) |
| **Сейчас запущено** (список) | — | Двойной клик — вернуть пульт к другому запущенному видео |

Плюс на самой странице работают горячие клавиши: `Space` — пауза, `←/→` — ±10 сек, `↑/↓` — громкость, `M` — звук, `C` — субтитры, `F` — развернуть.

### Пошагово

1. Вставьте ссылку в поле оверлея, выберите режим.
2. Нажмите **«📺 Открыть на ТВ»** — ссылка на страницу-плеер скопируется в буфер.
3. Вставьте её в телевизор в игре. Видео появится.
4. В оверлее загорится **«Пульт: ▶ играет 0:12/0:52 звук 80%»** — значит связь есть.
5. Жмите кнопки в оверлее — видео в игре слушается.

### Важное следствие: старт видео

Голый mp4 CEF часто не запускает сам (autoplay-политика). На странице-плеере есть **большая синяя кнопка «Нажмите, чтобы начать»** — она решает эту проблему. Если в игре есть возможность кликнуть по телевизору, кликните один раз и видео пойдёт. Дальше уже управляйте из оверлея.

### Субтитры

Субтитры подключаются к сессии параметром `sub=`. Поддерживается:
- локальный файл из папки `videos/` — `sub=subs.vtt`
- ссылка из интернета — `sub=https://site.com/subs.vtt`
- форматы: **VTT** (нативно) и **SRT** (конвертируется автоматически)

Сейчас в оверлее нет поля для субтитров — можно добавить ссылкой напрямую:
```
http://127.0.0.1:9000/new?url=ССЫЛКА&mode=get&title=Название&sub=subs.vtt
```
Откройте этот адрес в браузере — получите JSON с ссылкой `player`, её и вставляйте в телевизор.

### Качество видео

В пульте оверлея есть выпадающий список рядом с ползунком громкости:

```
Авто   1080p   720p   360p
```

Список заполняется сам, когда телевизор открыл страницу и видео загрузилось —
берётся из того, что реально предлагает сайт.

- **Авто** — hls.js сам подбирает качество под скорость интернета, как на YouTube.
- **1080p / 720p / 360p** — жёстко выбранное качество.

Как это устроено: Rutube (и многие подобные сайты) отдают каждое качество отдельным
потоком. Прокси собирает из них общий список (`master`-плейлист), и переключение
происходит на уже играющем потоке — **видео не останавливается и не начинает сначала**.
Позиция воспроизведения сохраняется, картинка меняется за 5–8 секунд.

То же самое можно выбрать **прямо на странице в телевизоре** — там справа внизу
тоже есть список (Авто / 1080p / 720p / 360p). Пригодится, если телевизор в игре
можно кликнуть мышкой.

Если список пустой или показывает только «Авто» — значит у этого видео сайт не даёт
выбора качества (обычный mp4-файл играет в одном качестве, менять нечего).

### Выбор озвучки

Кинотеатры рунета почти всегда показывают видео через плеер **Kodik** — и у него
на одну серию бывает 5–10 озвучек. Оверлей их видит и даёт переключать:

```
Озвучка: [ AniLibria.TV ▾ ]     ← список под кнопками пульта
```

Список заполняется сам при открытии видео. Переключение занимает 3–8 секунд,
позиция сохраняется (если сменили озвучку на 20-й минуте — там же и продолжится).

Как это устроено, если интересно: у Kodik каждая озвучка — это отдельный поток
со своим `id` и секретным хешем. Все они перечислены в скрытом списке внутри
страницы плеера. Прокси читает этот список, для каждой озвучки запрашивает
поток у плеера и расшифровывает ответ (шифр Цезаря + base64). Технически —
`/kodik-master?url=…&trans=<id>`.

Если у видео только одна озвучка, поле не показывается — переключать нечего.
У VK и YouTube озвучек нет: там одна дорожка, а «переозвучки» на VK — это
отдельные видео с другими ссылками.

### Возврат к уже запущенному видео

Когда вы ищете новое видео, старое **никуда не девается** — оно продолжает
играть в телевизоре. Всё, что было открыто, видно в списке под пультом:

```
Сейчас запущено (двойной клик — вернуть пульт):
  ★ 🟢 ▶ Очень странные дела, 1 сезон — AniLibria.TV
    🟢 ▶ aqz-KE-bpKQ                          (YouTube)
    ⚪ ⏸ https://m.vkvideo.ru/video-2200…     (пауза)
```

Что означают значки:

| Значок | Значение |
|---|---|
| ★ | видео, которым вы управляете сейчас |
| 🟢 | телевизор открыт и отвечает |
| ⚪ | страница закрыта (сессия ещё жива, но ничего не играет) |
| ▶ / ⏸ | играет / на паузе |

**Двойной клик по строке** — пульт переключается на это видео. Кнопки, полоса
прогресса, качество и озвучка сразу начинают управлять именно им. Ссылку заново
вставлять не нужно, старое видео не останавливается.

Список обновляется сам вместе с остальным состоянием. Кнопка **⟳** рядом —
обновить принудительно.

## 3. Почему не работают Кинопоиск, Netflix, IVI и подобные

Эти сервисы **физически не могут** играть через прокси, и это не баг:

| Причина | Что это значит |
|---|---|
| **DRM (Widevine)** | Видео зашифровано. Ключ выдаёт только приложение сервиса; браузер GTA 5 (CEF) не имеет этого модуля |
| **Вход по подписке** | Кинопоиск — Яндекс-паспорт, Netflix — аккаунт. Прокси не может «войти за вас» |
| **Защита от встраивания** | Сервис проверяет Referer/Origin и рвёт поток при попытке смотреть вне сайта |

Список известных сервисов, для которых прокси **сразу** выдаёт понятное объяснение (вместо зависания): Кинопоиск, Кинопоиск HD, Netflix, Disney+, IVI, Okko, Wink, More.tv, Premier, Start, Амедиатека.

**Что работает вместо них:** смотрите те же фильмы на открытых источниках (Internet Archive, Wikimedia), либо скачайте файл и раздайте через `/local/` — если у вас есть легально приобретённая копия.

### Что было исправлено

Раньше ссылка на Кинопоиск заставляла прокси «висеть» до 40 секунд (yt-dlp пытался разобрать страницу и ждал ответа), а оверлей в это время не отвечал. Теперь:

- **проверка ссылки занимает 0 секунд** для известных закрытых сервисов;
- у yt-dlp жёсткий таймаут (12 сек на сокет, 1 попытка) — он не может висеть;
- ошибка показывается **в пульте**, а не модальным окном, которое блокирует интерфейс;
- кнопки пульта **блокируются**, пока видео не готово — нельзя «нажать в пустоту»;
- опрос состояния не наслаивается: если предыдущий запрос не вернулся, следующий тик пропускается.

## 4. Как работает воспроизведение (без скачивания)

**Ключевой принцип: видео НЕ скачивается и НЕ конвертируется.** Прокси только помогает браузеру в игре получить поток.

```
Оверлей                    Прокси                      Телевизор в игре
   │                          │                              │
   │ вставляете ссылку        │                              │
   │ Rutube/VK/сайт           │                              │
   ├── /new?url=... ─────────►│ разрешает страницу в поток   │
   │◄─ /player/abc ───────────┤ (yt-dlp, ~1-2 сек)           │
   │                          │                              │
   │                          │◄─── открывает /player/abc ───┤
   │                          │──── HTML + hls.js ──────────►│
   │                          │◄─── /hls?url=playlist ───────┤
   │                          │──── m3u8 (переписан) ───────►│
   │                          │◄─── /hls?url=seg_001.ts ─────┤
   │                          │──── сегмент (байты) ────────►│
   │ ⏸ ⏪ ⏩ 🔊 CC ⛶ ⏹        │                              │
   ├── /control/abc?cmd=pause►│                              │
   │                          │◄─── /cmd/abc (опрос 250мс) ──┤
   │                          │──── исполняет pause ────────►│
```

**Что делает прокси:**
1. Превращает ссылку на страницу (Rutube/YouTube/сайт) в адрес настоящего потока — через yt-dlp, 1–2 секунды.
2. Отдаёт браузеру страницу-плеер с библиотекой **hls.js** (лежит локально в `static/hls.min.js`).
3. Проксирует сегменты потока, переписывая ссылки в плейлисте — это обходит **CORS** (иначе браузер не даст их скачать с чужого домена).

**Чего прокси НЕ делает:** не скачивает видео на диск, не конвертирует через ffmpeg, не занимает место.

### Поддерживаемые источники

| Источник | Формат | Качество | Звук | Как обрабатывается |
|---|---|---|---|---|
| **Rutube** | HLS (m3u8) | 360p–1080p | ✅ | играет напрямую, качества собираются в master |
| **YouTube** | HLS, видео и звук отдельно | 144p–2160p | ✅ | собираем master из двух дорожек — без скачивания |
| **VK Видео** | HLS, видео и звук отдельно | 128p–960p | ✅ | собираем master; ссылки VK требуют Chrome-заголовков |
| **Kodik** (плеер большинства кинотеатров) | HLS | 360p–720p | ✅ | расшифровываем поток через `/ftor` — **с выбором озвучки** |
| **Страница кинотеатра с Kodik** | HTML → плеер | — | ✅ | плеер находится на странице автоматически |
| **Прямые .mp4 / .webm** | файл | — | ✅ | проксируется потоком |
| **NASA, Wikimedia, Archive** | файл | — | ✅ | |
| **Twitch** — канал, запись, клип | HLS | 160p–1080p60 | ✅ | playback token через GraphQL, затем usher.ttvnw.net |
| **animego** (аниме-каталог) | HTML → Kodik | 360p–720p | ✅ | через `/api/player` — **все озвучки и серии** |
| **Dailymotion** | HLS | — | ✅ | через hls.js |
| **Кинопоиск, Netflix, IVI** | DRM | — | — | ❌ невозможно (см. раздел 3) |

**Важно про проверку:** всё из этой таблицы проверено живьём на реальных ссылках —
видео играет, звук идёт, качества переключаются, пульт работает.

### Почему нельзя просто открыть сайт в телевизоре

В GTA 5 телевизор — это **текстура**, а не окно. Кликнуть по кнопке «play» внутри него нельзя: курсор туда не попадает. Поэтому нужна страница-плеер, которой управляет оверлей — вы жмёте кнопки у себя, а страница слушается.

## 5. Ошибка видео, код 4 — что это и как исправлено

`MEDIA_ERR_SRC_NOT_SUPPORTED` — браузер получил ссылку, но не смог её декодировать.

### Причины и что с ними теперь

| Причина | Что было | Что стало |
|---|---|---|
| **HLS-поток (.m3u8)** — самый частый случай (Rutube, VK, Twitch) | прокси отдавал плейлист как `video/mp4`, CEF падал с кодом 4 | прокси **отдаёт плейлист в hls.js**, который играет его напрямую — без скачивания и конвертации. Сегменты идут через прокси (обход CORS) |
| **HTML-страница вместо видео** | `<video>` пытался декодировать HTML → код 4 | прокси **отказывает заранее** с объяснением: «ссылка ведёт на HTML-страницу». Нужна ссылка на сам поток |
| **H.265/HEVC, AC3, DTS** | чёрный экран без объяснений | ffprobe проверяет кодеки и пишет причину: «видео в H.265 — CEF его не поддерживает» |
| **Файл битый / недокачан** | код 4 молча | в панели сообщений: «кодек H.264 — должен поддерживаться, файл мог скачаться не полностью» |

### Что видно теперь при ошибке

- **На экране телевизора** — большое объяснение с кодом и расшифровкой («Код 4: формат не поддерживается — нужен MP4/H.264 или WebM»), кликом убирается.
- **В оверлее** — панель с причиной, кнопками «Повторить» и «Закрыть».
- **В пульте** — строка с кодом ошибки.

### Как не наткнуться на код 4

1. **Не вставляйте ссылки на сайты** (`https://site.com/film`) — это HTML. Нужна ссылка на сам файл/поток.
2. **Как найти настоящую ссылку**: откройте страницу в браузере → `F12` → вкладка **Network** → фильтр **Media** → запустите видео → найдите `.mp4` или `.m3u8` → скопируйте адрес.
3. **H.264 + AAC** — самый совместимый формат. Если файл в H.265/HEVC — CEF его не проиграет, нужна перекодировка:
   ```
   ffmpeg -i input.mp4 -c:v libx264 -c:a aac output.mp4
   ```

## 5a. Аниме-каталоги: animego и другие (озвучки + серии)

Проверено на `https://animego.me/anime/monolog-farmatsevta-3-3803`
(и его живом зеркале `animego.tv` — там адрес другой:
`/anime/monolog-farmacevta-3-season-8300`).

### Просто вставьте ссылку на страницу аниме

Прокси сам:

1. возьмёт **число из конца адреса** (у animego это ID аниме, например `8300`);
2. запросит у сайта `POST /api/player` — служебный запрос, который делает сам
   плеер animego при открытии страницы;
3. получит **все озвучки** и по каждой — **готовые ссылки Kodik на каждую серию**;
4. соберёт из них HLS-потоки с выбором качества 720p / 480p / 360p.

Ничего искать вручную не нужно: ни iframe, ни `.m3u8`.

### Что получается

| Что | Результат (проверено) |
|---|---|
| Озвучек в списке | **12** (AniMaunt, AniStar, AnimeVost, Anything Group, Deep, AniDUB, AniLibria, Dream Cast, Silver AniAge, Оканэ, Логово Любви, Субтитры Crunchyroll) |
| Серий на озвучку | **8** (3-й сезон выходит) |
| Качеств | 3 — 720p / 480p / 360p |
| Воспроизведение | ✅ все 12 озвучек играют, длительность 24 мин, ошибок нет |
| Переключение озвучки | ✅ из оверлея и с пульта, без потери места |

### Почему это работает

Kodik выдаёт ссылку на поток только тому, кто пришёл с «правильного» домена
партнёра: в запросе `/ftor` нужны подписи `d_sign`, `pd_sign`, `ref_sign`.
Прокси берёт их из HTML плеера, подставляя `Referer` сайта, на котором
плеер открыт. Поэтому работают и страницы каталогов, и ссылка на сам плеер.

Если сайт-партнёр неизвестен, прокси перебирает известные каталоги
(`animego.tv`, `animego.me`, `animego.org`, `kinogo.biz`, `hdrezka.ag`)
пока один из них не подойдёт.

### Если страница не открывается

`animego.me` отдаёт **HTTP 500 без тела** — это не блокировка,
сайт лежит (проверено и с нашего адреса, и через сторонний прокси).
Рабочее зеркало с теми же данными — **`animego.tv`**: адреса страниц
другие, но структура и озвучки те же. Если `.me` не открывается,
замените домен на `.tv` и найдите аниме поиском на сайте.

## 5b. Twitch: каналы, записи, клипы

Поддерживаются три вида ссылок — вставляйте как есть:

| Что нужно | Ссылка | Пример |
|---|---|---|
| **Живой эфир** | `twitch.tv/<канал>` | `https://www.twitch.tv/xqc` |
| **Запись (VOD)** | `twitch.tv/videos/<номер>` | `https://www.twitch.tv/videos/2937959097` |
| **Клип** | `twitch.tv/<канал>/clip/<код>` | `https://www.twitch.tv/имя/clip/Код` |

Ещё понимаются `m.twitch.tv/...` (мобильный адрес) и
`player.twitch.tv/?channel=...&video=...`.

### Что получается

| Параметр | Результат (проверено) |
|---|---|
| Качества | **1080p60, 720p60, 480p, 360p, 160p** |
| Звук | ✅ в каждом качестве |
| Переключение качества | ✅ 160p → 480p → 1080p, позиция не сбрасывается |
| Живой эфир | ✅ 1920×1080, идёт в реальном времени |
| Запись | ✅ 4.2 часа, перемотка работает |

### Как это устроено

1. Из ссылки берётся название канала или номер записи.
2. Через публичный GraphQL Twitch (`gql.twitch.tv/gql` и Client-ID веб-плеера)
   запрашивается **playback access token** — он нужен, чтобы попросить поток.
3. С этим токеном у `usher.ttvnw.net` берётся **master-плейлист** со всеми качествами.
4. Ссылки на качества заворачиваются в наш `/hls`-мост — иначе браузер в игре
   упрётся в CORS (Twitch не разрешает чужим страницам читать свои плейлисты).

### Если не работает

| Симптом | Причина |
|---|---|
| «Канал не в эфире» | стрим закончился — проверьте, идёт ли он в браузере |
| «Видео удалено или закрыто» | VOD удалён или доступен только подписчикам канала |
| Клип не открылся | клипы иногда удаляют; попробуйте открыть его в браузере |

**Важно:** Twitch не отдаёт записи, закрытые платной подпиской, и стримы
«только для подписчиков». Это ограничение самого Twitch, а не прокси.

## 5c. Разбор страницы со ссылкой на видео

Для сайтов, которые не входят в список поддерживаемых (онлайн-кинотеатры,
сериальные базы), приложение **само разбирает страницу** и достаёт из неё
ссылку на поток. Вставляйте в поле **адрес страницы**, а не плеера:
`https://site.com/1-season/1-seriya/`

### Что делает прокси

| Шаг | Что происходит |
|---|---|
| 1 | Загружает саму страницу |
| 2 | Ищет ссылки `*.m3u8` в HTML и во **всех** скриптах |
| 3 | Разворачивает экранированные варианты: `https:\/\/…` и `\u002F` — так сайты прячут адреса в JSON |
| 4 | Проверяет параметры `file=`, `src=`, `video_url=`, `hls=`, `stream=` |
| 5 | **Собирает ссылку из кусочков**, если плеер держит её частями: `base` + `id` + `/index.m3u8` |
| 6 | Заглядывает **внутрь iframe** (до 3 уровней) — плеер почти всегда там |
| 7 | **Проверяет каждый поток запросом** — живой он или сервер отвечает 403/404 |

Отдельных кнопок «Найти поток» и режимов поиска в интерфейсе нет: разбор
страницы включается сам, когда ссылка ведёт на HTML-страницу, а не на файл.

### Почему ссылка выглядит странно

У многих плееров адрес потока — **подписанный и временный**, вида:

```
https://kalarona.org/s/FEblpk2WGjWNsdhDyVtOQg/1795425119/330274/index.m3u8
                    └── токен ─────────────┘ └ время ┘ └озвучка┘
```

- **токен** выдаётся конкретному браузеру на сессию;
- **число** в середине — время выдачи (Unix-время);
- **последнее число** — идентификатор озвучки (AMedia, LostFilm и т.п.).

Такой адрес нельзя «запомнить»: через несколько минут он перестаёт
работать, а при открытии с чужого адреса CDN отвечает **403**.
Поэтому прокси:

1. собирает такие адреса из кода страницы;
2. **сразу проверяет** их и помечает живой/закрытый;
3. играет только те, что реально отдают плейлист.

Если живых нет — нужна свежая ссылка из своего браузера (см. ниже),
вставленная в оверлей сразу после запуска видео.

### Что означают пометки

| Пометка | Значение |
|---|---|
| **живой** | сервер отдал плейлист — поток можно включать |
| **доступ закрыт** | ссылка привязана к сессии браузера/CDN или уже истекла |
| **в странице** | ссылка лежала прямо в HTML |
| **внутри плеера** | нашли в iframe (самый частый случай) |
| **в параметре** | ссылка была в параметре вида `?file=…` |
| **собран плеером** | адрес склеен из частей: `base` + `id` + `/index.m3u8` |
| **через разборщик** | сработал запасной путь через yt-dlp |

### Если поток не нашёлся

Плеер собирает ссылку скриптом уже после клика — в тексте страницы её нет.
Тогда:

1. Откройте видео в обычном браузере.
2. `F12` → **Сеть** → фильтр **Медиа** (или `m3u8` в строке фильтра).
3. Запустите видео, найдите строку `index.m3u8`.
4. Правый клик → **Копировать → Копировать ссылку**.
5. Вставьте эту ссылку в оверлей и нажмите **Открыть на ТВ**.

Прокси умеет играть прямую `.m3u8` — ему не нужна страница.

Чтобы такая ссылка не исчезала через несколько часов, нажмите **Закрепить**:
прокси скачает поток к себе и отдаст постоянный адрес.

### Важное ограничение

Некоторые сайты (`watch-the-sopranos-online.net`, `strannye-dela.online`)
блокируют **серверные и VPN-адреса**: отдают `403 — Turn off your VPN` или
рвут соединение. С домашнего интернета они открываются нормально, поэтому
разбор страницы работает у вас в игре, даже если в проверке из датацентра
сайт ругается.

## 5d. Хранилище: почему «занято 4 ГБ» при пустой папке

**Было:** приложение сообщало о переполнении хранилища, хотя файлов почти нет.

**Причина:** в `videos/cache/` оставался **скачанный фильм на 4 ГБ** — он
появлялся каждый раз, когда видео грузили через скачивание. В поставку такой
файл не входит, а сам кэш никто не чистил.

**Что сделано:**

- «Скачать и раздать через /local» убрано из подсказок — этот способ больше
  не предлагается, потому что он и забивал диск;
- появился отдельный файл `cleanup.py` — чистит кэш и временные профили;
- приложение при старте удаляет из кэша файлы старше суток.

Запуск очистки вручную:

```bat
python cleanup.py
```

## 5j. Постоянные ссылки: как поймать поток, который живёт только в сессии браузера

Проблема, с которой сталкиваются все кинотеатры с озвучками: `.m3u8`
содержит подписанный токен. Он умирает через 30–60 минут, а иногда и
привязан к cookie вашего браузера. Скопировали — вставили в телевизор —
через полчаса «manifestLoadError».

### Как это решено: «закрепление»

Кнопка **«Закрепить»** (в блоке постоянных ссылок) делает из временной
ссылки постоянную в три шага:

1. **Запоминает сессию.** Прокси сохраняет не только адрес, но и всё, по чему
   CDN узнавал «своего»: `Referer`, `Origin`, `User-Agent` и **cookie**
   из вашего браузера. Это запись в `videos/pins.json`.
2. **Скачивает файл.** ffmpeg один раз забирает поток и склеивает его в
   `videos/cache/pin_<id>.mp4` — без перекодирования, так что качество
   не меняется.
3. **Отдаёт свою ссылку.** Наружу уходит `http://<ваш-ip>:9000/v/<id>.mp4`.
   Она не протухает: файл лежит у вас на диске, сайт больше не участвует.

### Важно: телевизор можно включать сразу

Не нужно ждать конца скачивания. `/v/<id>.mp4` поддерживает `Range` и
отдаёт байты **по мере готовности** файла: включили — пошло воспроизведение,
остальное докачивается в фоне. Если файл ещё совсем пустой, прокси ответит
понятной страницей «Файл ещё готовится» вместо ошибки 4 в игре.

### Как пользоваться

1. Откройте видео в обычном браузере, включите нужную озвучку и дайте ему
   пойти 3–5 секунд — плеер построит ссылку на поток.
2. `F12` → **Сеть** → фильтр `m3u8` → правый клик по строке →
   **Копировать ссылку**.
3. Вставьте её в поле оверлея и нажмите **Закрепить**.
4. Через секунду в поле «Ссылка для телевизора» появится
   `http://…/v/<id>.mp4` — она уже в буфере обмена. Вставляйте в телевизор.

Ссылка сохраняется между запусками программы: блок **«Закреплённые ссылки»**
показывает всё, что закреплено, с размером файла и статусом
(`готово` / `качается N%` / `ошибка`). Двойной клик — открыть на телевизоре,
«Удалить» — стереть запись и файл.

### Почему это надёжнее «просто скопировать .m3u8»

| | Копирование .m3u8 | Закрепление |
|---|---|---|
| Живёт | 30–60 минут | пока файл на диске |
| Cookie браузера | не передаются → 403 | сохраняются |
| Переключение серии | каждый раз заново | один раз на серию |
| Нагрузка на сайт | повторные запросы | ровно одна загрузка |

### Ограничения (честно)

* Закрепляется **тот поток, который вы поймали**. Если сайт выдаёт на каждую
  серию свою ссылку — закрепляйте каждую серию (это 2 клика).
* Поток скачивается целиком — на сериал уходит ~500–1500 МБ. Место смотрите
  в `videos/cache` (кнопка «Удалить» рядом с каждой записью).
* Закреплять надо, **пока ссылка жива**. Если прошло больше часа — возьмите
  свежую ссылку в браузере (F12 → Сеть → `m3u8`) и закрепите заново.
* Если у сайта защита по IP или по безголовому браузеру, скачивание может не
  пойти — тогда в логе (`/pin/log?id=…`) будет причина, а в списке — `ошибка`.

### Что появилось в API

| Маршрут | Что делает |
|---|---|
| `/catch?port=9222` | Ловит `.m3u8` из браузера **вместе с cookie и заголовками** |
| `/pin?url=…[&referer=…&cookies=…]` | Запомнить сессию и начать скачивание |
| `/pins` | JSON: список закреплённых (id, статус, размер, ссылка) |
| `/pin/status?id=…` | Состояние одной записи |
| `/pin/log?id=…` | Лог скачивания (почему не вышло) |
| `/unpin?id=…` | Удалить запись и файл |
| `/v/<id>.mp4` | Постоянная ссылка (Range, отдаёт по мере скачивания) |

## 5k. Правки по двум скриншотам: дубли кнопок и «раздувание» блоков

### Кнопки пульта дублировались

**Было:** рядом с треугольником «пуск» появлялся ещё один треугольник, а
рядом с колонкой — эмодзи динамика.

**Причина:** состояние подставлялось через `setText("▶")` / `setText("🔇")`,
но у кнопок уже была иконка. Получалось «иконка + символ» — визуально два
элемента.

**Исправлено:** меняется сама иконка, текст не трогается:

```python
self.btn_play.setIcon(self._icon("pause") if playing else self._icon("play"))
self.btn_mute.setIcon(self._icon("muted") if muted else self._icon("volume"))
```

Заодно из интерфейса убраны все эмодзи (⏸ ▶ 🔊 ✅ 🔒 🟢 ⚪ ⏳): на части
систем шрифт их не содержит, и вместо значка рисовался пустой квадрат.
Статус теперь читается словами: «Пульт: пауза  12:34/45:00  звук 100%»,
в списке сессий — «● играет · Название».

### Блоки растягивались после скрытия соседних

**Было:** скрыли список потоков — карточка «Сейчас запущено» раздувалась на
треть экрана; вернуть прежний размер окно не могло.

**Причина:** две независимые проблемы.

1. `QVBoxLayout` раздавал «лишнюю» высоту первой карточке (у неё оставался
   коэффициент растяжения 1). Виджет с `Preferred` по вертикали спокойно
   забирает всё свободное место.
2. При скрытии виджета Qt **не уменьшает окно**: освободившееся место
   остаётся в окне, и его делят оставшиеся карточки.

**Исправлено:**

* у всех карточек `QSizePolicy(Preferred, Fixed)` и **нулевой** stretch —
  они всегда ровно по содержимому;
* единственный «пожиратель» лишней высоты — распорка в конце layout;
* добавлен `_fit_height()`: после каждого показа/скрытия окно
  пересчитывается по сумме высот видимых карточек. Ширина не трогается —
  её пользователь мог выставить сам;
* все переключения идут через `_show_card()` / `_hide_card()`, которые и
  вызывают пересчёт.

Проверено: 761 px → показали список потоков 1003 → скрыли **763** →
показали закреплённые 999 → скрыли **763**. Карточка пульта всегда 226 px,
«Сейчас запущено» — 68 px, сколько бы блоков ни скрыли.

## 5l. Исправление manifestLoadError + убраны «Найти поток» и «Открыть в браузере»

### Почему сломалось то, что работало

Две причины, обе в прокси.

**1. Каждый HLS-сегмент уходил в yt-dlp.** Функция `_resolve_media_url`
проверяла только `.m3u8 / .mp4 / .webm`. Сегменты HLS — это `.ts` и `.m4s`,
они не подходили, и КАЖДЫЙ уходил в `resolve_input()` -> yt-dlp -> падение
с `DownloadError`. На один сегмент уходили секунды и ошибка. hls.js не получал
вовремя куски и показывал `manifestLoadError` на всех источниках сразу.

Исправлено: список расширений расширен (`.ts .m4s .aac .m4a .mp3 .vtt .mov
.mkv .mpd`), плюс отдельно ловятся ключи шифрования (`/key`) и файлы без
расширения. Проверка медиа теперь занимает 0 мс вместо 0.6-2 с.

**2. Всегда выбиралось максимальное качество.** Rutube отдаёт 360p / 720p /
1080p. Код брал 1080p (8.6 Мбит/с = ~3.3 МБ каждые 4 секунды). На канале
или CDN, который не держит такую скорость, буфер не наполняется — снова
`manifestLoadError`. Теперь прокси собирает master-плейлист со всеми
качествами, и hls.js сам выбирает по скорости и переключается на лету.

### Заодно ускорена отдача

* порции 64 КБ вместо 1 МБ + flush() — сегмент уходит сразу, а не пачками;
* request_queue_size = 128 — hls.js открывает до 6 соединений одновременно;
* daemon_threads, allow_reuse_address.

### Убрано из кода и интерфейса

| Что | Где было |
|---|---|
| Кнопка «Найти поток на странице» | overlay.py, btn_sniff |
| Карточка списка найденных потоков | overlay.py, sniff_box |
| Метод `_sniff_page()` | overlay.py |
| Кнопка «Открыть в браузере» (глобус) | overlay.py, btn_test |
| Метод `_open_result()` | overlay.py |
| `import webbrowser` | overlay.py |
| Маршрут `GET /sniff` | proxy.py |
| Маршрут `GET /players` | proxy.py |

«В игре» теперь просто копирует ссылку (раньше ещё и открывала браузер).
Позже удалено и «Из моего браузера» вместе с окном выбора потоков
(`StreamsWindow`) и подключением к отладочному порту браузера — см. 5m.

Новый маршрут: `GET /rutube-master?url=...` — master со всеми качествами.

### Кнопки

| Изменение | Подробности |
|---|---|
| Возвращена кнопка «Посмотреть в браузере» | В блоке «Ссылка для телевизора в игре», иконка глобуса рядом с копированием. Открывает системный браузер с готовой ссылкой — быстрый способ проверить, работает ли поток. |
| Удалена кнопка «Из моего браузера» | Вместе с методами `_catch_from_browser`, `_sniff_done`, `_pick_stream`, классом `StreamsWindow`, маршрутом `GET /catch` в proxy.py и ярлыком-инструкцией в подсказке. |
| `icons/globe.svg` возвращён | Используется новой кнопкой. |

### Почему поток падал: таймауты hls.js

Прокси отдаёт сегменты нормально — замер показал 6 параллельных сегментов за 9 с.
Проблема была в плеере: стандартные таймауты hls.js (10 с на манифест,
20 с на сегмент) не хватало, когда CDN отдавал медленно, и плеер сдавался
с `manifestLoadError`.

Исправлено в конфиге hls.js (player.py):

```js
manifestLoadingTimeOut: 30000,   // было 10000
levelLoadingTimeOut:    30000,
fragLoadingTimeOut:     60000,   // сегмент 3 МБ на слабом канале
manifestLoadingMaxRetry: 4,
fragLoadingMaxRetry:     6,
startLevel: -1                   // старт по скорости сети, а не 1080p
```

Плюс авто-понижение: если загрузка сегмента падает, плеер уходит уровнем
ниже и показывает «Сеть не тянет — понижаю качество» вместо ошибки.

## 7. Три режима — когда какой

### 🅰️ YouTube (играет напрямую, без скачивания)

```
Вставляете: https://www.youtube.com/watch?v=XXXX
Режим:      YouTube
```

YouTube отдаёт видео и звук **отдельными HLS-дорожками**. Прокси собирает из них
один общий поток (`/yt-master`) — hls.js играет его целиком, со звуком.

- **Ничего не скачивается** и не занимает место на диске;
- доступны все качества: 144p–2160p, переключаются на ходу, как на самом YouTube;
- позиция и громкость — из оверлея.

Старый способ (скачать в кеш) остался как запасной через `/yt?url=…` — он нужен,
если интернет в игре нестабилен: скачанный файл играется без сети.

### 🅱️ Любой сайт (поток)

```
Вставляете: https://ru.wikipedia.org/... или https://site.com/page-with-video
Получаете:  http://127.0.0.1:9000/r?url=…
```

Самый универсальный режим. Что происходит по шагам:

1. **Ссылка на видео** (Rutube, VK Видео, Twitch-запись) — играет напрямую, с качествами.
2. **Ссылка на страницу кинотеатра** — прокси ищет на странице плеер Kodik и
   переключается на него. Дальше — обычное видео с выбором озвучки.
3. **Ссылка прямо на плеер Kodik** (`kodik.info/serial/…` или `kodikplayer.com/…`) —
   сразу открывается, со всеми озвучками.
4. **На странице цельный MP4/WebM** — прокси отдаёт его потоком, не скачивая.
5. **HLS (m3u8)** — играет через hls.js напрямую.

Поддерживается 1800+ сайтов через yt-dlp плюс собственные разборщики для VK,
Kodik и YouTube.

### 🅲 Прямой файл (прокси)

```
Вставляете: https://site.com/a.mp4
Получаете:  http://127.0.0.1:9000/get?url=https%3A%2F%2Fsite.com%2Fa.mp4
```

Для источников, которые не отдают файл без заголовков браузера. Прокси подставляет User-Agent и сохраняет Range-запросы — телевизор в игре сможет перематывать.

## 10a. Кодировки: если в именах файлов «кракозябры»

Симптом: после распаковки архива имя файла выглядит как `л6_л3лХу лО_лЭрл3лрлВлМ.txt`
или `РЎ_Р§Р•Р“Рћ_РќРђР§РђРўР¬.txt` вместо `С_ЧЕГО_НАЧАТЬ.txt`.

Причина — не в самих файлах, а в **архиваторе**. Имя внутри zip хранится байтами;
чтобы кириллица читалась правильно, к имени должен быть прикреплён флаг UTF-8.
Некоторые старые архиваторы его игнорируют и показывают имя в кодировке Windows
(cp866 / cp1251) — отсюда «кракозябры».

Что сделано в этом архиве:

- архив собран программой, которая ставит флаг UTF-8 у каждого имени — Windows
  Explorer, 7-Zip, WinRAR и встроенный распаковщик Windows 10/11 показывают имена верно;
- памятка положена **дважды**: `С_ЧЕГО_НАЧАТЬ.txt` (по-русски) и `KAK_NACHAT.txt`
  (то же самое латиницей) — если одно имя всё же не читается, открывайте другое;
- **все имена файлов кода и папок — латиницей** (`proxy.py`, `static/`, `github-pages/`),
  поэтому даже самый старый распаковщик не сможет их испортить;
- все `.py`/`.md`/`.txt` — UTF-8 без BOM; `.bat` — UTF-8 **с CRLF**, и в них первым
  делом выполняется `chcp 65001`, поэтому русский текст в консоли читается;
- в питоновском коде везде явно указан `encoding="utf-8"` при чтении и записи файлов,
  а `console_io.py` принудительно переключает вывод консоли на UTF-8 и никогда не падает
  из-за символа, который нельзя закодировать.

Если кракозябры всё же видны:

1. Распакуйте архив **7-Zip** (правый клик → 7-Zip → Извлечь) — он определяет кодировку
   имён автоматически.
2. В WinRAR: «Извлечь…» → вкладка «Дополнительно» → «Кодировка имён файлов» → **UTF-8**.
3. Если имя всё равно битое — просто переименуйте файл вручную: на работу кода имя
   памятки не влияет, а имена `.py`/`.bat` всегда латиницей и не повреждаются.

## 10b. Озвучка и качество: два исправленных бага

### Озвучка «возвращается на первую»

**Было:** выбираете озвучку — список перескакивает обратно на первую.

**Причина:** страница-плеер сообщала прокси **старый номер озвучки**. Номер
(`TRANS_INDEX`) задавался один раз при загрузке страницы и при переключении
не обновлялся. Оверлей видел «страница говорит 0» и честно возвращал список
на первое значение — хотя поток уже шёл в новой озвучке.

**Исправлено:** при смене озвучки страница обновляет и номер, и название.
Плюс добавлена страховка в оверлее: если вы только что выбрали озвучку,
а страница ещё не подтвердила — список держит ваш выбор (до 8 секунд),
а не откатывается.

**Проверено:** 12 переключений подряд — все 12 раз индекс и название
совпадали, поток продолжался с той же секунды.

### LevelLoadError на единственной озвучке

**Причина:** Kodik в ответе на `/ftor` иногда указывает качество, которого
у видео **нет**. Например, заявляет три варианта `720 / 480 / 360`, но под
ключом «720» отдаёт ссылку на файл `480.mp4` — тот же самый, что и для «480».

hls.js видел `RESOLUTION=1280x720`, начинал загрузку, получал поток
854×640 и падал с `LevelLoadError` при переключении.

**Исправлено:** прокси сверяет **фактическое качество по имени файла**
(`480.mp4` → 480) и выкидывает дубли ссылок. В мастер-плейлист попадают
только реально существующие варианты.

| Было | Стало |
|---|---|
| 720 → 480.mp4, 480 → 480.mp4, 360 → 360.mp4 | 480 → 480.mp4, 360 → 360.mp4 |

**Проверено:** LevelLoadError больше не возникает, переключение работает.

### «641p» вместо «480p»

Потоки часто имеют паддинг: кадр 854×640 — это на самом деле 480p с
чёрными полосами, 640 вместо 480. Подпись качества бралась из высоты кадра
напрямую, отсюда «641p».

**Исправлено:** высота нормализуется по стандартному ряду
(144/240/360/480/540/720/1080/1440/2160), причём сверяется **ширина** —
она паддингом не искажается.

| Кадр | Подпись |
|---|---|
| 854×641 | 480p |
| 854×640 | 480p |
| 1920×1088 | 1080p |
| 1280×721 | 720p |

### Качество меняется «не сразу»

hls.js доигрывает буфер старого качества — иногда 20+ секунд. В игре это
выглядит как «кнопка не работает». Теперь буфер вычищается сразу
(`stopLoad` → `startLoad` с текущей позиции), переключение мгновенное.

## 11. Решение проблем

### Прокси не поднимается

Статус в правом верхнем углу панели показывает реальное состояние. **Кликните по статусу** — откроется лог `proxy.log` с последними 40 строками.

Что делает оверлей при проблемах:
- пишет лог запуска в **`proxy.log`** (рядом с `start.bat`);
- при сбое показывает **окно с причиной** (порт занят / нет модуля / процесс упал);
- если порт 9000 занят **посторонней программой** — автоматически берёт 9001, 9002 и т. д.;
- если на порту уже работает **наш** прокси (запущенный ранее) — переиспользует его и помечает «(внешний)».

Кнопка **⟳** рядом со статусом — перезапуск прокси без закрытия оверлея.

| Проблема | Решение |
|---|---|
| В логе `UnicodeEncodeError: 'charmap' codec can't encode character` | **Исправлено в этой версии.** Причина: русская Windows пишет вывод в cp1251, где нет эмодзи. Теперь `console_io.py` переключает вывод в UTF-8, а оверлей передаёт `PYTHONIOENCODING=utf-8` дочернему процессу. Если увидели эту ошибку — вы запускаете старую версию, распакуйте архив заново |
| `[ОШИБКА] Python не найден` | Установите Python 3.12 с python.org, отметьте «Add to PATH», запустите `start.bat` снова |
| `Не удалось установить зависимости` | Проверьте интернет. Попробуйте: `.venv\Scripts\python.exe -m pip install --upgrade pip` и запустите `start.bat` снова |
| Окно не поверх игры | Игра должна быть в оконном режиме **Borderless** (окно без рамки). В настройках GTA: «Графика → Режим экрана → Без рамки». Статус «Поверх игры» должен быть включён |
| Оверлей «не кликается» | Нажмите Alt+Tab или кликните по иконке в панели задач — клики по окну игры перехватываются игрой |
| Статус «прокси: остановлен» | Кликните по статусу → смотрите `proxy.log`. Частая причина — порт 9000 занят. Оверлей сам уходит на 9001+; если и это не помогло — освободите порт: `netstat -ano | findstr :9000` → `taskkill /PID <номер> /F` |
| Прокси на порту 9001 (не 9000) | Это нормально: порт 9000 был занят другой программой. Ссылки в оверлее уже указывают на правильный порт — копируйте их оттуда |
| Ссылка открывается в браузере, а через прокси — 502 / 403 | **Ошибка видео, код 4** | Браузер не смог декодировать ссылку. **Исправлено:** m3u8 конвертируется в MP4, HTML отвергается заранее, кодеки диагностируются. Смотрите раздел 4 |
| Пульт «завис» на Кинопоиске/Netflix | **Исправлено.** Эти сервисы требуют DRM и вход — прокси теперь отвечает мгновенно и объясняет причину. Смотрите раздел 3 |
| `module 'urllib' has no attribute 'request'` | **Исправлено** — был пропущен импорт. Распакуйте архив заново |
| Ошибка появляется **за** окном оверлея | **Исправлено.** Модальные окна заменены на встроенную панель сообщений внутри оверлея — она всегда на виду. Кнопки «Копировать», «Повторить», «Закрыть» рядом |
| Не могу кликнуть по оверлею / он «улетел» | **Исправлено.** Убран флаг `Qt.Tool`: теперь окно есть в панели задач и на панели Alt+Tab. Esc больше НЕ скрывает окно (раньше это была ловушка — вернуть было нельзя). Для справки есть кнопка **«? Помощь»** |
| Источник закрыт антиботом (Cloudflare). Прокси уже обходит это Firefox-отпечатком и curl-фолбэком. Если всё равно не идёт — скачайте файл через `download_and_prepare.py` и раздайте через `/local/` |
| В игре чёрный экран | Ссылка ведёт не на файл. Проверьте в браузере: откройте ссылку, должно начаться видео. Если в браузере работает, а в игре нет — формат не поддержан (нужен mp4/webm) |
| YouTube: «только раздельные потоки» | Используйте мод Media Player V или скачайте заранее (`download_and_prepare.py`), раздайте через `/local/` |
| Видео дёргается / буферизуется | Прокси работает через локальную сеть — проверьте, что игра и прокси на одном ПК. Для тяжёлых 4K используйте 720p-версии |
| `ffmpeg не найден` | Запустите `start.bat` — он ставит `imageio-ffmpeg`. Проверьте: `.venv\Scripts\python.exe ffmpeg_bin.py` |
| Ссылка работает, но перемотка не работает | В ссылке нет `Range`-поддержки; используйте режим `/yt` (кеш) или `/local/` — там все файлы раздаются с Range |

### Где посмотреть логи

- Оверлей: запустите `run_console.bat` — откроется консоль с логами.
- Прокси: автоматически пишется в **`proxy.log`**. Кликните по статусу в панели, чтобы посмотреть последние строки.
- Прокси запускается оверлеем автоматически; для отдельной диагностики: `.venv\Scripts\python.exe proxy.py`
- Кеш: `videos/cache/` — какие файлы уже скачаны.

## 12. Важные нюансы

### Производительность
Оверлей на PySide6 — обычное окно Qt, он **не** встраивается в игру магически, а висит поверх (Always On Top). В полноэкранном режиме (Fullscreen) окна Windows могут терять фокус — поэтому рекомендуется **Borderless**.

### Античит / GTA Online
Прокси и оверлей — **сторонний софт**, который читает и пишет только свой буфер обмена и сеть. В **GTA Online** использование стороннего софта не приветствуется и может привести к блокировке; в **одиночной игре** (Story Mode) ограничений нет. Используйте в сингле.

### Место на диске
Кеш YouTube растёт: один ролик 10 минут 720p ≈ 80–150 МБ. Чистить: удалите файлы из `videos/cache/` — прокси скачает заново при необходимости.

### Безопасность
Всё работает **локально**: прокси слушает 127.0.0.1 и недоступен из сети. Не меняйте хост на `0.0.0.0` без необходимости — тогда к вашим видео сможет подключиться любой в локальной сети.

### Авторские права
Прокси работает офлайн-посредником: вы смотрите видео так же, как в браузере. Публиковать чужие фильмы на GitHub Pages или файлообменниках — нарушение; для личного просмотра в игре всё в порядке.

```bash
# Активировать окружение
```

## 15. Диагностика: что делать, если «не работает»

Приложение ведёт журнал: всё, что запрашивалось, что ответил CDN,
какие ошибки прислал плеер в игре, сколько секунд заняла подготовка,
плюс снимок окружения (Python, ffmpeg, yt-dlp, сеть, порты).

### Как снять отчёт

1. Воспроизведите ошибку (чтобы она попала в журнал).
2. В панели нажмите **«?» рядом с заголовком «Ссылка на видео»**.
3. Откроется окно **«Диагностика»**.
4. Нажмите **«Копировать»** и пришлите текст.

### Что в отчёте

```
=== СНИМОК ОКРУЖЕНИЯ ===
python: 3.13.18 (Windows 10)
машина: AMD64, процессор 8 ядер
локальный IP: 192.168.1.42
порты 9000/9001: занят / свободен
ffmpeg: C:/.../ffmpeg.exe — ffmpeg version 7.0
yt-dlp: 2026.10.26
CDN (сеть): ok (DNS 12 мс, TCP 443 открыт)
запущено: 23.11 16:03:21
событий в журнале: 42
файл журнала: C:/Games/gta-video-host/diag.log

=== ЖУРНАЛ СОБЫТИЙ ===
16:03:24 req    200 river-3-355.rtbcdn.ru…/1080p_stream.m3u8  code=200
16:03:26 req    200 river-3-355.rtbcdn.ru…/seg_2026…218296.ts  code=200
16:03:31 ОШИБКА CDN не отдал плейлист: cdn.example/x/index.m3u8  code=403 error=HTTPError: Forbidden
16:03:34 ИГРА   ошибка в игре: поток: manifestLoadError (критично) HTTP 403 …/index.m3u8
16:03:36 new    готово за 8.2 с: rutube.ru/video/9ae8…
```

Ключевые метки:

| метка | что значит |
|---|---|
| `req` | запрос прошёл, код 2xx/3xx |
| `ОШИБКА` | CDN отказал, обрыв, ошибка подготовки — **с кодом и текстом** |
| `ИГРА` | ошибка, присланная из браузера телевизора (hls.js) |
| `boot` | страница открылась **в телевизоре** — виден его браузер (User-Agent), загрузился ли hls.js, есть ли MSE |
| `new` | сколько секунд заняла подготовка ссылки |

### Если видео чёрное и молчит

- **Есть `boot`, нет ошибок** — страница открылась, но видео не пошло.
  Смотрите строку `boot`: если `hls=НЕ загружен`, телевизор не смог
  скачать `/static/hls.min.js` или движок слишком старый.
- **Нет ни одного `boot`** — телевизор вообще не достучался до прокси:
  неверный IP в ссылке, другой Wi-Fi, файрвол Windows.
- **`boot` есть, через 12 с `ошибка в игре: 12 с, видео не готово`** —
  страница открылась, а до CDN нет: обычно это качество или блокировка по IP.

### Что искать в первую очередь

- **`готово за N с`** — если больше ~20 с, телевизор сдаётся раньше, чем
  начинается воспроизведение. Причина в источнике, не в оформлении.
- **`CDN не отдал плейлист … code=403/404`** — ссылка устарела или
  CDN блокирует IP. Нужна свежая ссылка из оверлея.
- **`ошибка в игре … fragLoadErrorTimeOut`** — сеть не тянет качество:
  в пульте поставьте «360p» вместо «Авто».
- **`CDN (сеть): ошибка`** — DNS/файрвол: проверьте интернет и VPN.
- **`порты 9000/9001: занят`** — прокси не поднялся, порт занят.
  Перезапустите `start.bat`.

Файл `diag.log` лежит рядом с программой и хранит последние 2 МБ
(при переполнении старый становится `diag.log.1`).
