# Стайлгайд

Правила, которые **проверяются инструментами**. Если правило здесь есть,
но его нельзя проверить — оно помечено «ревью».

Основа: PEP 8 + Ruff + mypy (раздел 14 инструкции).

---

## 1. Инструменты

| Задача | Инструмент | Команда |
|---|---|---|
| Форматирование | `ruff format` | `make fix` |
| Линтер | `ruff check` | `make lint` |
| Типы | `mypy` | `make types` |
| Тесты | `pytest` | `make test` |

Спор о стиле решает инструмент, а не ревьюер. Если инструмент
не прав — меняется конфигурация в `pyproject.toml`, а не код вручную.

---

## 2. Именование

| Что | Стиль | Пример |
|---|---|---|
| Модуль | `snake_case`, по смыслу | `diagnostics.py`, не `utils2.py` |
| Класс | `PascalCase` | `SessionStore`, `ProxyHandler` |
| Функция | `snake_case` | `prepare_source`, `render_player` |
| Переменная | `snake_case` | `session_id`, `playlist_raw` |
| Константа | `UPPER_SNAKE_CASE` | `MAX_FILE_BYTES`, `MEDIA_EXTS` |
| Булева | `is_/has_/can_/should_` | `is_cached`, `has_audio` |
| Приватная | `_` в начале | `_route_index`, `_build_filename` |

Запрещено:
- сокращения, кроме общепринятых (`id`, `url`, `http`, `hls`, `ts`);
- имена-заглушки: `data2`, `tmp`, `obj`, `result` без смысла;
- `utils`, `common`, `misc`, `helpers` как имена модулей.

Русские имена и строки разрешены и приветствуются: интерфейс русскоязычный.
Транслит в именах переменных — запрещён (`nazvanie` → `title`).

## 3. Размер и сложность

| Показатель | Лимит | Проверка |
|---|---|---|
| Длина функции | 40 строк | ревью |
| Вложенность | 4 уровня | ревью |
| Цикломатическая сложность | 15 | `ruff C901` |
| Длина строки | 100 | `ruff E501` |
| Аргументов у функции | 5 (свыше — объект-параметры) | ревью |

Если функция не влезает — декомпозируйте по шагам, а не по строкам.
Пример из проекта: `_prepare_source` (200 строк, сложность 28) разбит на
`_prepare_anime`, `_prepare_kodik`, `_prepare_twitch`, `_prepare_rutube`,
`_prepare_generic_page`, `_prepare_vk`, `_prepare_youtube` — каждый ≤ 45 строк.

---

## 4. Модули и строки

- Модуль начинается с docstring: **что** он делает и **почему** существует.
- Модуль без `#!/usr/bin/env` и без объявления кодировки (Python 3 — UTF-8 по умолчанию).
- Импорты: стандартная библиотека → сторонние → свои. Сортирует `ruff I001`.
- Неиспользуемые импорты удаляются (`ruff F401`).
- `from __future__ import annotations` — в начале каждого модуля.
- Глобальное состояние — только с явным `_lock` и комментарием, зачем.

---

## 5. Функции и классы

- Публичная функция — docstring с описанием, аргументами, возвратом, ошибками.
- Docstring объясняет **почему так**, а не пересказывает код.
- `raise … from e` при пробросе (`ruff B904`).
- Никаких `except Exception: pass` без комментария `# noqa: BLE001 — причина`.
- Возврат по одному типу: не `dict | None | False`.
- Инварианты — через `assert` с сообщением (в проде они дёшевы).

Пример хорошего docstring:

```python
def _file_ext(url: str) -> str:
    """
    Расширение выходного файла по адресу источника.

    Смотрим ТОЛЬКО путь, без строки параметров: в адресах вида
    `/stream?file=a.webm` расширение из параметра не должно влиять на имя
    файла — иначе mp4-поток сохранится как .webm и не откроется на телевизоре.
    """
```

## 6. Константы и конфигурация

- Магические числа и строки — в константы с именем (вверху модуля).
- Настройки, которые меняет пользователь, — в переменные окружения или файл,
  не в код.
- Порты, таймауты, лимиты — именованные константы с единицей в имени:
  `TIMEOUT_SECONDS`, `MAX_FILE_BYTES` (а не `TIMEOUT`, `MAX`).

Проверка: `ruff PLR2004` (magic-value-comparison).

---

## 7. Ошибки и логирование

- Логи структурированы: `диагностика` пишет `kind`, `text` и поля-ключи.
- Уровни: `req`/`new` — обычные события, `err` — отказ, `player` — от ТВ.
- **В логи не попадают секреты**: `token`, `sig`, `key`, `session`, `cookie`
  заменяются на `***` (`diagnostics.SECRET_QUERY_KEYS`).
- Ошибка пробрасывается с контекстом: `raise RuntimeError(f"CDN: {e}") from e`.
- `print` разрешён только в точках входа (`__main__`, `main()`).

---

## 8. JavaScript в странице плеера

Страница открывается в браузере телевизора, где нет отладчика.

- **Только ES5**: без `=>`, `const`, `let`, `?.`, `??`, шаблонных строк.
  Проверка: `tests/test_player.py::TestEs5Compatibility`.
- `"use strict"` внутри IIFE.
- Никаких `console.log` в отдаваемой странице.
- Данные извне (заголовок, URL) экранируются при вставке в HTML.
- Таймауты и ретраи hls.js — именованные константы с комментарием,
  почему такие значения (см. ERR-001).

---

## 9. QSS / UI

- Цвета и отступы — только в `style.qss`, не в коде.
- Состояния `normal/hover/pressed/focus/disabled` — для каждой кнопки.
- Отступы кратны 4. Поля ввода: `padding: 8px 12px`, `radius: 6px`.
- Иконки — SVG через `QIcon`, не эмодзи (ломаются в системных шрифтах).
- Позиционирование — только layouts, `setGeometry`/`move` запрещены.
- Внутри `QLabel` — экранированный HTML (`html.escape`), не f-строка с данными.

## 10. Документация

- `README.md` — назначение, запуск, тесты, конфигурация.
- `CHANGELOG.md` — что изменилось для пользователя.
- `ERRORS.md` — ошибки и решения, живой документ.
- `docs/adr/` — значимые решения: контекст, решение, последствия.
- `TODO`/`FIXME` — только с номером задачи: `TODO(#12): …`.

## 11. Быстрая проверка перед коммитом

```bash
ruff format src tests && ruff check src tests && mypy src && pytest -q
```

Пять секунд — и CI не станет красным из-за забытой запятой.
